# 基于真实菜价与植物大战僵尸策略的末日蔬菜种植推荐系统

> PvZ Economy Engine V2.0 正在按批次重构。当前已完成项目基础、植物映射、组合优化和 Streamlit UI；数据流水线与正式评分仍待补齐。

本项目把北京地区真实蔬菜价格与植物策略属性结合，回答一个可解释的问题：在有限阳光、格子和攻防需求下，末日环境中种植哪些蔬菜植物最有性价比。

## V2.0 目标链路

```text
北京新发地真实菜价或本地 CSV
    -> 日期、菜名和价格单位清洗
    -> 移动均价、涨跌幅、波动率和价格分位数
    -> 植物与现实蔬菜映射
    -> 末日性价比指数与推荐理由
    -> 阳光/格子/攻防约束组合优化
    -> PvZ 风格 Streamlit 看板
```

## 版本边界

V2.0 只保证一个地区、一个可解释模型和一条可离线运行的主链。以下内容不属于本版本：

- Airflow 调度和多地区 SaaS；
- Alpha、夏普比率等金融指标；
- 复杂回测、影子价格和金融化叙事；
- Prophet、XGBoost 等非必要重模型；
- 官方 PvZ 图片、音效或其他版权素材。

旧仓库中的相关文件暂时保留用于迁移核对，但已经标记为 legacy，不应继续扩展。详见 [LEGACY.md](LEGACY.md)。

## 快速开始

建议使用 Python 3.10 或 3.11。

```bash
python -m venv .venv
pip install -r requirements.txt
python -m unittest discover -s tests -v
```

运行兼容 CLI：

```bash
python cli.py --sun 150 --cells 20
```

运行 Streamlit：

```bash
streamlit run app.py
```

页面包含阳光计数器、僵尸模式、植物种子卡、五列草坪布局、菜价趋势、推荐排行和逐植物推荐理由。修改侧栏的僵尸模式、阳光或格子数后，Streamlit 会重新计算并刷新推荐。

第 2 批完成前，页面使用 `data/fallback/vegetable_prices.csv` 离线样例；第 4 批参数确认前，页面明确显示“兼容推荐指数”，不会把旧 `utility` 冒充正式末日性价比指数。页面素材仅由 emoji 和原创 CSS 构成。

## 植物映射规则

`data/plants.csv` 是 V2.0 的植物参数与现实蔬菜映射表。每一行代表一种植物，标准字段如下：

| 字段 | 含义 |
|---|---|
| `name` | 植物名，必须唯一 |
| `vegetable_name` | 用于关联菜价的标准蔬菜名 |
| `sun_cost` | 游戏策略中的阳光成本 |
| `attack` | 兼容旧流程的相对攻击值，后续评分前会归一化 |
| `defense` | 防御能力评分，范围 0-10 |
| `production` | 资源产能评分，范围 0-10 |
| `control` | 减速、视野等控制能力评分，范围 0-10 |
| `special_ability` | 特殊能力的可读说明 |
| `role` | 在推荐组合中的主要定位 |

映射遵循以下规则：

1. 优先直接对应同名或同类作物，例如豌豆射手映射豌豆、土豆雷映射土豆、樱桃炸弹映射樱桃。
2. 没有直接现实作物时，根据外形、功能或种植用途选择代理蔬菜，例如向日葵映射同属产能型油料作物的油菜，坚果类防御植物映射耐储存的大白菜。
3. 映射值必须使用菜价数据中的标准菜名，不在运行时进行模糊猜测。多种植物可以映射到同一种蔬菜。
4. 当前 15 种植物均能与 `data/fallback/vegetable_prices.csv` 精确关联；第 2 批完成后，同一字段会关联清洗结果中的 `name`。

`hp`、`special_tag` 和 `category` 是重构期间保留的 V1 兼容列，用于确保旧 CLI 和页面仍可启动。属性值是项目内部的策略参数，不宣称等同于官方游戏数据。

## 组合优化

`src/optimizer.py` 接收植物评分并最大化组合总评分。评分字段按 `apocalypse_index`、`score`、`utility` 的顺序识别，因此第 4 批完成后无需修改优化公式即可接入末日性价比指数。

整数规划包含四项约束：

1. 总阳光消耗不超过可用阳光；
2. 植物总数量不超过格子数；
3. 至少包含 1 个攻击植物；
4. 至少包含 1 个防御或控制植物。

防御或控制候选由明确的分类、定位，或不低于 5 分的防御/控制属性识别。正常情况下使用 PuLP；未安装 PuLP 或 CBC 求解器不可用时自动切换到贪心 fallback。返回结果包括植物组合、数量、总阳光、总评分、求解方式、逐项约束检查和推荐摘要。

## 数据与素材原则

- 原始菜价必须记录来源、采集时间、原始单位和转换规则。
- 网络数据源不可用时必须自动使用仓库内的离线样例。
- `data/processed/` 文件只能由清洗流程生成。
- 植物图标只能使用自绘、emoji 或明确允许再分发的资源。
